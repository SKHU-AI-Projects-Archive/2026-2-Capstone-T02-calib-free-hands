# Real-data (Phase C) protocol

This protocol was written before the synthetic gate was evaluated, so that the
decision rule could not be shaped by the gate outcome. **Whether any of it ran
is recorded in `results/summary/gate.json` under `real_phase`.**

## The gate rule

The GigaHands phase runs only if all four required synthetic gates pass
(`g2`, `g3`, `g6`, `g7` — see `synthetic_test_protocol.md`). If any fails, the
status is `REAL_FOCAL_PHASE_NOT_RUN` and nothing below is executed.

This is the point of a synthetic gate. A cue that cannot recover a *known*
focal from data generated by the very model the solver assumes will not become
interpretable on real data, where the hand model, the articulation source and
the camera are all additionally wrong. Running it anyway would produce a number
that could not be read either way.

## What would run, in order

1. **`characterize_real_bilateral_disagreement.py`** — measure how far apart the
   left and right reference bone proportions actually are in GigaHands, per
   subject, using `OTHER_CAMERA_ONLY_REFERENCE_3D`. This is a prerequisite, not
   a result: if the observed disagreement is far outside the synthetic
   asymmetry range tested, the synthetic evidence does not transfer and that
   must be stated before any focal number is produced. Written up in
   `reference_geometry_disagreement.md`.

2. **`build_real_manifest.py`** — the `64GRID_BILATERAL_DEVELOPMENT` split:
   sequences where both hands are present in the same frames, on the
   development cameras only. Frozen to a manifest with a SHA-256 before any
   focal is estimated. The 64-frame approximation is never called a `full
   sequence` or a `whole-video result`.

3. **Subject-identity audit** — confirm that a left and a right hand compared
   with each other belong to the same session and the same performer. Without
   this the bilateral premise is not established on real data at all.

4. **R0–R4 camera-nuisance conditions**, as in CAM-EXP-008: how much of any
   result survives pre-specified perturbation of the principal point and
   distortion, which are not primary inputs here.

5. **LOCO** (leave-one-physical-camera-out, 40 folds) as the primary protocol,
   LOSO (5 folds) secondary. Statistical unit `(sequence, camera)`
   (`SEQUENCE_CAMERA_UNIT`); physical-camera cluster bootstrap, 10,000
   iterations.

6. **Paired-input audit** — the compared conditions must share an identical
   frame manifest. If they differ by even one frame, the comparison is not
   reported as primary.

## Constraints that hold whatever happens

- The GigaHands reference focal is never an optimisation input. It is read only
  at evaluation time.
- The `FINAL_CONFIRMATORY_HOLDOUT` (InterHand2.6M / HanCo) is not opened.
- Dataset-provided 2D is not called `GT2D`; dataset-provided 3D is not
  called `independent physical ground truth`.
- The single-focal rig confound (`SINGLE_FOCAL_RIG_CONFOUND`) applies: the
  GigaHands reference focal has a CV of only 1.73–1.90 %, and a constant scores
  0.85–0.91 %. Any real-data result must be compared against that constant, not
  against zero.
- Observed left/right disagreement in GigaHands is not described as true human
  anatomical asymmetry; it contains reconstruction error of unknown size.
- Success on synthetic data would not, by itself, be claimed to generalise to
  GigaHands or to a factory deployment.
