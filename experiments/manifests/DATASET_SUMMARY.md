## GT availability, stated precisely

Three of the five datasets do **not** ship an independent 2D keypoint
annotation. This matters for what CAM-EXP-001 can actually prove:

- **GigaHands** — the only true independent 2D-vs-projection test. Its
  `keypoints_2d` are per-view 2D *detections* with confidence, produced
  per camera, so disagreement can come from the detector as well as from
  our convention. This makes it the most informative and the noisiest source.
- **AssemblyHands (`demo`)** — `annotations[].keypoints` reproduces the
  projection to 0.0000 px, i.e. the shipped 2D was generated by exactly the
  projection we implement. This verifies our camera maths bit-for-bit but is
  *circular*: it cannot detect an error shared with the dataset authors.
- **InterHand2.6M** — validated against the annotated per-image `bbox`,
  an independent 2D quantity, though a much weaker (containment-only) test.
- **HanCo** — no 2D annotation at all. Validated geometrically (positive
  depth, in-image rate) plus visual overlay on real RGB.

of each dataset is recorded in its manifest JSON.

## Annotation sets found on disk

- **InterHand2.6M**: `all` (test, train), `human_annot` (test, train),
  `machine_annot` (test, train, val). `human_annot/test` is used by
  CAM-EXP-001.
- **AssemblyHands**: `demo` (16 images, full GT), `test-iccv2023`
  (calib + data + abs_depth, joint_3d only as a prediction template),
  `test-eccv2024` (62043 images, GT withheld).

Each JSON carries `archives` with size, SHA256 and an integrity result, plus
`important_files` with SHA256 for the key GT files. Per-file rows carry
`path`, `size_bytes`, `modified_utc`, `extension`; SHA256 is deliberately not
computed for every unpacked file because the archive hash already pins them.
